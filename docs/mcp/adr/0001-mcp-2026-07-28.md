# ADR-0001: Stateless MCP 2026-07-28 jako kanonický remote protokol

- Stav: přijato
- Datum: 2026-08-08
- Rozsah: remote HTTP a lokální stdio Node server

## Kontext

Tender Flow potřebuje bezpečně vystavit tenantová data AI klientům bez sdílené
serverové MCP session a bez obcházení existujícího uživatelského oprávnění.
Nová revize MCP přináší stateless core, request metadata, header-based routing,
cache hints a posílený autorizační model.

## Rozhodnutí

Kanonická remote implementace používá SDK v2 a MCP `2026-07-28`. Každý request
je samostatný; identita je OAuth Bearer token uživatele Tender Flow. Tools a
resources se registrují podle explicitních interních permissions oddělených od
standardních OAuth identity scopes, ale autoritativní datový
přístup zůstává v Supabase RLS/RPC. Zápisy používají explicitní aplikační stav
proposal místo skryté transportní session.

## Důsledky

Pozitivní:

- instance lze horizontálně škálovat bez MCP session affinity,
- gateway může routovat a měřit podle MCP headers,
- resource cache je explicitně private a časově omezená,
- uživatel, OAuth klient a idempotency jsou dohledatelné.

Náklady a omezení:

- klient musí správně implementovat OAuth/resource binding a novou revizi,
- aplikační proposal stav vyžaduje databázové tabulky a cleanup,
- distribuovaný DB limiter přidává jednu atomickou RPC operaci před každým
  tool/resource handlerem a fail-closed závislost na databázi,
- `desktop MCP` zůstává do sjednocení samostatnou legacy implementací.

## Zamítnuté varianty

- service-role MCP: příliš široké oprávnění a riziko obcházení RLS,
- automatické write tools bez potvrzení: nevyhovující dopad prompt injection a
  chybných agentních rozhodnutí,
- dlouhodobá skrytá MCP session: zvyšuje provozní stav a vazbu na instanci.

## Ověření

Rozhodnutí se ověřuje protokolovými testy, JWT/scope negativními scénáři,
resource private cache testy a produkčním OAuth/RLS canary. Sjednocení desktopu
vyžaduje nové ADR nebo aktualizaci tohoto záznamu.
